## 実装した内容

| 作業 | 変更と目的 | 状態 |
|---|---|---|
| T5 診断 | 初期データの取得・適用・ACK・再試行、カメラ前後のviewportと操作UI座標を端末内に最大400件記録。本文・写真・認証情報を記録しない | 実装済み |
| T1 教師モーダル | 初期データより先に届いた編集差分を保持し、初期データ適用後に順番どおり反映。遅れて取得したデータにも差分を再適用。古い監視セッションと版不一致を排除 | 実装済み |
| T1 受信確認・復旧 | 教師側での適用完了ACKを追加。通信送信成功だけでは初期同期完了としない。欠落検知・タイムアウト時は回数を制限して再取得し、解消しない場合は再読み込みを案内 | 実装済み |

| T4 重複アップロード | 通常保存と監視用保存を行き来する場合も既存の同一画像を再利用。同一パスへの同時アップロードを一本化。既存の競合時復旧は維持 | 実装済み |
| T6 授業条件の確認 | 公開版・認証済み教師と生徒・実機での確認 | 未実施 |

## 検証結果

- `npm.cmd test`：全項目成功。追加した `test-monitor-recovery.mjs` では順序逆転、重複、差分欠落、履歴上限、古い監視要求、上書きされたsnapshot、適用ACK、再試行上限、診断情報の除外を検証した。教師・生徒の実ソースのハンドラをVMで実行するが、通信はローカルの代替実装。
- 画像保存テスト：通常／監視用パス切替での再利用と、同一パスの同時保存が1回のアップロードになることを確認。既存の欠落画像テストが出す警告は意図した異常系の出力。
- `npm.cmd run test:browser:monitor-recovery`：Windows Edge・仮想カメラ・ローカル2ページで成功。1366×768、1280×600、1024×576、683×384、375×667の5サイズ。撮影→挿入→他ページへの画像復元→移動・縮小→Undo、撮り直し→キャンセル、カメラ停止、操作UIの座標保持と実クリックを確認。ページ例外なし。
- ブラウザ結果とスクリーンショット：`output/playwright/monitor-recovery/`。外部通信と認証を無効にしたfixtureであり、本番RealtimeやStorageのE2Eではない。
- 初期調査の `output/incident-20260929/` は修正前の証拠として保存。そこにある不具合再現スクリプトは修正後の合格テストではない。

ブラウザテストにはPlaywrightとEdgeが必要。今回使用した設定例：

```powershell
$env:PLAYWRIGHT_MODULE='C:\Users\sotso\.cache\codex-runtimes\codex-primary-runtime\dependencies\node\node_modules\playwright'
npm.cmd run test:browser:monitor-recovery
```

## 公開後の確認順序

公開は別途承認後に行う。全参加端末を更新版に再読み込みしてから、まず教師1台＋生徒2〜3台で以下を確認する。生徒作品は削除せず、確認用ページ・確認用データを用いる。

1. Cクラス s014 または同条件の生徒で、描画を続けながら教師がモーダルを開く。読み込み完了と最新内容を確認し、閉じて開き直しても再現しないことを確認。
2. モーダル表示中に生徒が写真を挿入・移動・拡大縮小・Undo。教師側の表示と一致することを確認。教師による編集も反映されることを確認。
3. 通信を短く切断して戻し、欠落から復旧すること、復旧できない場合も読み込み表示が無期限に続かず再読み込みできることを確認。
4. Aクラス s009 のChromebookで撮影・挿入・撮り直し・キャンセルを実施。通常画面／全画面と当日の表示倍率で、ヘッダー・ツールバーが見えることと実際に操作できることを確認。
5. 少人数で問題がなければ、当日と同じクラス分割・教師配置で約20人に拡大し、一操作ずつ同期結果を確認。保存不能・内容不一致・操作不能が出た時点で拡大を止め、時刻と診断情報を回収する。

診断の取得は教師・生徒それぞれのブラウザコンソールで以下を実行する。端末のメモリ内のみで、自動送信されず、ページ再読み込みで消えるため、問題直後に取得する。

```javascript
window.classWhiteboardDiagnostics.export()
```

C/s014の当日の原因はイベント履歴不足で断定していない。A/s009のChromebook症状はWindows上では修正前から再現できておらず、今回のカメラ対策をもって解消確認済みとはしない。
